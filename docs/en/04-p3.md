# 04 — P3: freeze the policy, then sweep low bits

P3 is an *executed* synthetic sweep (four `_rsi` operators — `rmsnorm`, `softmax`,
`layernorm`, `gemv` — bare-metal Triton/PTX, fixed random data, no model change).
Its target is the pool's best low-bit configuration, never a paper leaderboard. Its
selection rules must exist before the data does.

## 1. Why `policy.md` is frozen first

Rules written after seeing results can always be bent toward a flattering group.
So:

- the rules live in `p3/policy.md`;
- its sha256 lives in `p3/policy.sha256`;
- `p3/select.py` verifies the hash before reading any pool and exits on mismatch;
- `selection.json` embeds `policy_version` and `policy_sha256`.

Changing the policy means re-freezing it and bumping the version, which invalidates
old selections by construction.

## 2. Rules, applied in order

| Rule | Content |
|---|---|
| **R1 divergence** | any arm with a diverged seed is excluded; if the FP16 control arm diverged, the task is excluded |
| **R2 accuracy** | best arm = highest mean `fp16_val_acc` with `mean ≥ ref - 0.0015`; ties break on lower total bits, then config id |
| **R3 selection** | `best ≥ pool FP16 mean - 0.0035`, and if a caveat exists, `best > caveat + 0.002` |
| **R4 family** | group by `mechanism_class`; adopt the class with the most selected tasks provided it has ≥ 3; ties break on median gain, then class name; otherwise fall back to task level with `family: null` |
| **R5 joint impact** | any headline for a combination must be a measured joint run of that exact combination; a sum of per-class impacts is a planning estimate only |
| **R6 citation** | P1 may cite only classes P3 selected, never a class from a paper |

R3.b exists because a weak FP16 reference would make every arm look "good enough".

## 3. Pool format

`p3/pool.json` is written by GPU-side `p3/measure_pool.py` (currently `blocked`):

```json
{
  "kind": "hgk_p3_pool",
  "device": "NVIDIA RTX 6000D",
  "policy_sha256": "…",
  "tasks": [{
    "id": "rmsnorm-b4096-h7168",
    "mechanism_class": "rmsnorm",
    "seeds": [1,2,3,4,5],
    "fp16_val_acc": 0.6123,
    "trials": [{"logical": 3, "bits": {"w": 6}, "seed": 1,
                "fp16_val_acc": 0.6119, "diverged": false, "tok_per_s": 412.5}]
  }],
  "fp16_acc_caveat": {"…": 0.6001},
  "per_class_impact_pct": {"rmsnorm": 1.8},
  "joint": {"mechanisms": ["rmsnorm"], "value": 1.4, "source": "evidence/p3/joint.json"}
}
```

Raw trials are mandatory: R1 (divergence) and R2 (per seed) cannot be audited from
an aggregate.

## 4. Output

```bash
python3 -m p3.select --pool p3/pool.json --out p3/selection.json
```

`selection.json` carries the policy version and hash, the pool hash, the pool-wide
FP16 mean, per-task `selected / best / reasons[]` (including rejections), `family`,
`selected_mechanisms`, the `joint` status, and the `p1_mechanism_classes` that P1
may cite.

`joint.status` is either `measured` (that exact combination was run) or
`requires_joint_measurement`, in which case only `planning_sum_pct` is reported and
explicitly labelled as not the joint value.

## 5. Current status

Policy and selector are implemented and tested locally
(`tests/test_p3_select.py`, 13 cases, including tamper detection). `p3/pool.json`
does not exist and no `selection.json` was produced.

An exploratory timing pass did run on the RTX 6000D host:
`p3/measure_op_timings.py` wrote `p3/evidence/pool_20261115T151201.json` and
`p3/evidence/pool_20261115T151323.json` (8 operators, 20 rounds, 256 MiB L2
flush). It measures the shipped call against a same-bytes reference only. It has
no low-bit arms, no `fp16_val_acc`, and does not follow the pool schema, so it
cannot drive `p3.select`. Therefore **no P3 number** appears in the README or in
any verdict — deliberately, since a public number must come from a rerunnable,
registered measurement.
