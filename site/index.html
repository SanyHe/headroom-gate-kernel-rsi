Repository Gate spec

Kernel research · pre-registered · replayable

Work out the hardware ceiling before you write the kernel.

Most kernel work only asks “how much faster than before”, never “how much headroom is left against the hardware”. This project flips the order: work out the lowest time the bytes and FLOPs allow (floor), then how much a rewrite could possibly win (ceiling), and only then decide whether it is worth writing. GO if the conservative estimate clears 1.3× — worth building. Under 1.15× is NO-GO. In between is INCONCLUSIVE: an open question, not a failure. One measured case on the AutoDL RTX 6000D replays offline; five pre-registered templates await third-party cloud measurement.

01

The gate

Bytes

Sum the bytes that must move: weights, activations, output. This number has no bargaining room. A mechanism can only remove what it actually covers.

Floor

max(bytes / BW_eff, flops / FLOP_eff), both measured. A same-bytes reference kernel can raise the floor and can never lower it.

max( B / 1.613 TB/s , F / 136.8 TFLOPS )

Verdict

GO needs the conservative end at or above 1.30×, plus a same-bytes floor, at least 5 repeats and CV within 2%. NO-GO if even the generous end stays under 1.15×. Everything else falls through.
